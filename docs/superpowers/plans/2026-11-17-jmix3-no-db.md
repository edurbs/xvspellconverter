# JMix 3.1 Upgrade + Database Removal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn xvspellconverter into a database-free JMix 3.1.0 app that keeps the public Xavante orthography converter with its 558-word exception dictionary embedded in the app.

**Architecture:** Hexagonal layout stays: the `GetWordGateway` port gains an in-process adapter (`GetWordDictionaryGateway`) backed by a TSV resource instead of the DataManager-backed Postgres adapter. All data-layer infrastructure (JPA entities, Liquibase, Postgres, security-data, datatools) is deleted; JMix security continues in anonymous-only mode over `InMemoryUserRepository`. Tasks 1–4 run on JMix 2.3.0 to keep every commit green; Task 5 bumps the framework.

**Tech Stack:** Java 21 (Temurin, user-local `~/.jdks`), Gradle 9.8.0 wrapper, JMix 2.3.0 → 3.1.0 (Spring Boot 4.1, Vaadin 25.3), plain JUnit 5 tests.

**Spec:** `docs/superpowers/specs/2026-11-17-jmix-3-upgrade-design.md`

## Global Constraints

- Final state: **no database anywhere** — no Postgres driver, no EclipseLink/JPA, no Liquibase, no `main.datasource.*`, no DataManager usage
- JMix versions: start `2.3.0`; final `id 'io.jmix' version '3.1.0'` + `bomVersion = '3.1.0'`; Gradle wrapper `9.8.0`; Java 21
- Public behavior must not change: letter rules (z→dz, s→ts, â→ö, i→ĩ, `'`→ꞌ, nbsp→space) plus case-sensitive exact dictionary lookups on the **post-letter-conversion** word
- Every Gradle invocation needs the JDK: `JAVA_HOME=$(ls -d ~/.jdks/jdk-21*)` prefix (JDK installed in Task 1; `~` = `/home/eduardo`)
- Commands run from the repo root `/home/eduardo/vscode/xvspellconverter`
- Tasks 1–4 must leave `./gradlew test` green before committing (baseline today is RED: old tests need the unreachable LAN Postgres; Task 1 makes the suite DB-free and green)
- Javadoc-verified APIs: `io.jmix.core.security.InMemoryUserRepository` and `io.jmix.security.role.RoleGrantedAuthorityUtils` exist with the used signatures in both JMix 2.3 and 3.1

## Review Focus

Failure modes the unit tests can't catch, most likely first:

1. **Anonymous view access after the security rework** — a person opening the site with no session must see the converter page, not a login redirect or 403. Pinned by the boot smoke test (curl `/` → HTTP 200 with "Conversor") in Tasks 4 and 5.
2. **PWA icon under Vaadin 25 default-deny** — `/icons/icon.png` must serve 200 after the upgrade; pinned by curl in Task 5. If it 403s, the `SecurityFilterChain` from Task 4 is wrong or shadowed.
3. **Unicode dictionary entries** — words containing ꞌ, ã, é (seed entries like `Abiꞌata`) must round-trip through the TSV with exact match; pinned by Task 1 test entries chosen from those rows. If a lookup misses, suspect the extraction sed or file encoding.
4. **Dictionary + suffix interaction** — "Mozésihi" → strip "hi" → lookup "Modzés" (post-conversion form) → seed miss → letter-rules-only "Modzésihi"; pinned in Task 1's rewritten `ConvertUseCaseTest` (seed-only expectation, DB-only entries lost per user decision). If it fails, the TSV must contain the post-conversion `from` spelling, not the original.
5. **Production jar path** — after Task 4 sets `productionMode = false` (Vaadin 25 flow), building a deployable production jar now requires `-Pvaadin.productionMode=true`; document this in the commit message / final notes since no test exercises deployment.

```java
package com.company.xvspellconverter.infra.security;

import io.jmix.core.security.InMemoryUserRepository;
import io.jmix.security.role.RoleGrantedAuthorityUtils;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.User;
import org.springframework.stereotype.Component;
import org.springframework.context.annotation.Primary;

@Primary
@Component("UserRepository")
public class AppUserRepository extends InMemoryUserRepository {

    private final RoleGrantedAuthorityUtils roleGrantedAuthorityUtils;

    public AppUserRepository(RoleGrantedAuthorityUtils roleGrantedAuthorityUtils) {
        this.roleGrantedAuthorityUtils = roleGrantedAuthorityUtils;
    }

    @Override
    protected UserDetails createSystemUser() {
        return buildUser("system", FullAccessRole.CODE);
    }

    @Override
    protected UserDetails createAnonymousUser() {
        return buildUser("anonymous", AnonymousRole.CODE);
    }

    private UserDetails buildUser(String username, String roleCode) {
        return User.builder()
                .username(username)
                .authorities(roleGrantedAuthorityUtils.createResourceRoleGrantedAuthority(roleCode))
                .passwordEncoder(p -> p)
                .build();
    }
}
```

package com.company.xvspellconverter.infra.security;

import io.jmix.flowui.security.JmixSecurityFilterChainOrder; // resolve exact package via compiler if different
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.annotation.Order;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class StaticResourcesSecurityConfiguration {

    @Bean
    @Order(JmixSecurityFilterChainOrder.CUSTOM)
    SecurityFilterChain iconsFilterChain(HttpSecurity http) throws Exception {
        http.securityMatcher("/icons/**")
                .authorizeHttpRequests(authorize -> authorize.anyRequest().permitAll());
        return http.build();
    }
}
